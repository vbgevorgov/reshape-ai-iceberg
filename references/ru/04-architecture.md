# Шаг 4/5 — Architecture & AI Engineering

Сначала опиши гарантии бизнес-системы и только затем подбирай механизм: детерминированные правила и код, поиск по документам/retrieval, математическая оптимизация, прогноз/ML, симуляция, языковая модель, инструментальные агенты. Для каждой необходимой части укажи вход, выход, почему выбран метод, возможный отказ и эталонный тест.

Не применяй LLM для расчётов, требующих точности транзакционной системы. Не добавляй отдельный agent harness, если достаточно штатной оркестрации. Сложная архитектура должна доказывать свою необходимость инвариантами предметной области, а не названием AI.

Если агенты оправданы: роли, конкретные tools и права, versioned context, границы памяти, state machine, бюджеты вызовов, max retries, stop conditions, human approval, журнал причин и безопасное восстановление. Различай агента-исследователя, агента разработки и агента будущей клиентской системы. Loop Engineering: «наблюдай → анализируй → действуй → оцени → исправляй» с условиями входа, повтора, остановки и эскалации; отделяй цикл разработки от цикла бизнес-решения.

Опиши наблюдаемость, доступность, обслуживание, резервное копирование, откат, информационную безопасность, ошибки API и ручной fallback. Изобрази краткую схему потоков данных и границ доверия; явно отметь компоненты, которые **не требуются** на MVP.

Выход: минимально достаточная архитектура, инженерные допущения, условия перехода к агентам/ML и границы безопасности.
